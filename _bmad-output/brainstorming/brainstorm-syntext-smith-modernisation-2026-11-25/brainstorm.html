Brainstorming session · 25 November 2026

Modern approaches for Syntext Smith

Goal: Decide how to rebuild Syntext Smith for current LLM capabilities.

A code review set the context for the session. The neuro-symbolic AST and compiler path has no caller. Chat uses free text plus regex extraction. Smith uses a single provider, Gemini, and the default model is gemini-1.5-flash. Smith has no system instruction field, structured output, tool calls, streaming or image input. Auto-fix supports three languages, with regex patchers ahead of the LLM.

Technique 1 of 8 · Ideas 1 to 15

Assumption Reversal

Each card strikes out one assumption in the current build. The reversal sits under the struck assumption.

1

Reverse "the model cannot be trusted with syntax".

Let the model write native Mermaid, PlantUML and BPMN directly, and delete the JSON AST schema and the compiler.

Feeds direction A
2

Reverse "validation happens after generation".

Give the model a validate tool that the model calls until the real parser passes.

Feeds direction A
3

Reverse "the model returns a whole diagram".

The model returns targeted edits (search and replace, or line patches) against the current code.

Feeds direction B
4

Reverse "chat is the surface".

Add an inline prompt bar in the editor (Cmd-K on a selection) that needs no sidebar.

5

Reverse "the user applies code".

Edits stream into the editor as a pending diff, and the user accepts or rejects each hunk.

Feeds direction B
6

Reverse "one provider".

Put Gemini, Claude, OpenAI and local models behind one provider-neutral tool-calling adapter.

7

Reverse "the editor fixes the diagram type".

The model chooses the type through a set_diagram_type tool call and shows the reason.

8

Reverse "text in".

Accept a pasted whiteboard photo or screenshot and return an editable diagram.

9

Reverse "the model never sees the picture".

Send the rendered PNG back to the model so the model critiques layout and legibility.

Feeds direction C
10

Reverse "regex patchers first, LLM last".

Run LLM repair first with the real parser error, and keep a deterministic step only for BPMN layout.

Feeds direction A
11

Reverse "the prompt carries the syntax rules".

Fetch the relevant syntax reference for the active diagram type on demand, using the docs links already in DIAGRAM_TYPES.

12

Reverse "suggestions are text parsed by regex".

Return suggestions as a typed field of a structured reply.

13

Reverse "history is a list of messages".

History becomes a list of diagram versions, so the user can branch and revert.

14

Reverse "Smith waits to be asked".

Smith notices a render error and offers the fix on the error banner.

15

Reverse "the key lives in the browser".

Offer an optional thin proxy so a team shares a managed key.

Technique 5 of 8 · Ideas 58 to 67

TRIZ Contradiction

Each card sets two forces against each other. The text under the two forces resolves the contradiction.

58

Reliability against expressiveness:

full native syntax plus a real-parser tool loop gives both, where the restricted AST gave only reliability.

Feeds direction A
59

Privacy against validation:

PlantUML validation needs Kroki, so offer a self-hosted Kroki address and a clear notice, or a WebAssembly build in the browser.

60

Speed against correctness:

show the first draft at once, repair in the background, and badge the result "verified" when checks pass.

61

Control against automation:

auto-apply small safe edits with undo, and require diff review for structural changes.

Feeds direction B
62

Context size against cost:

for a large BPMN file, send a compact outline of ids, names and flows, and let the model request XML sections by id.

63

BPMN verbosity against token limits:

the model emits a compact process description or modelling operations, and the app expands and lays out the XML.

Feeds direction D
64

Breadth against depth:

tiered support, with "verified" types that have validators and evaluations, and "best effort" types labelled as such.

65

Bring-your-own-key simplicity against security:

key in a header, session storage by default, opt-in to remember.

66

Chat history against truth:

the diagram is the state; the history is summarised and the current code is always authoritative.

67

Model freedom against house style:

express conventions as lint rules that the tool loop enforces.

Synthesis · Out of the forge

Six insights and five chosen directions

Six insights tie the 102 ideas together. The final decision names five directions, A to E.

The six insights

  1. Insight 1

    Ideas 1, 2, 10, 41 and 58 are one idea: native syntax plus real validators as tools. That single change retires the AST compiler, the regex patchers, the language detector and most prompt rules.

    A Direction A: tool loop with native syntax and real validators

  2. Insight 2

    Ideas 3, 5, 42, 54 and 61 are one idea: targeted edits shown as a reviewable diff with undo. The existing semantic diff modal is the asset to build on.

    B Direction B: targeted edits with diff review

  3. Insight 3

    Ideas 9, 22, 76 and 80 are one idea: the model looks at the rendered diagram. Visual self-critique addresses layout quality, which parsers cannot judge.

    C Direction C: render-and-look plus image input

  4. Insight 4

    Ideas 17, 63 and 89 show where a symbolic stage still wins: BPMN layout. BPMN with auto-layout and round-trip visual editing is Smith's clearest difference from a general chat assistant.

    D Direction D: BPMN as the focus area

  5. Insight 5

    Ideas 16, 23, 24 and 52 are the precondition for every other change: an evaluation set, so each model or prompt change is measured.

    E Direction E: provider layer and evaluation set first

  6. Insight 6

    Idea 46 (editor as an MCP server) answers idea 88 from the other side: if users already work in a general assistant, bring the validators, converters and renderers to that assistant.
